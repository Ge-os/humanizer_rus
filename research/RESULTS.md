# Исследование: ранжировщики синонимов для гуманизатора

Этап 1 — простые методы (lesk, ngram, pmi) на метрике перплексии.
Этап 2 — тяжёлые методы (sklearn, локальный ONNX-детектор) на реальном AI-детекторе.

## Настройка

- **Тексты**: 30 русских ИИ-текстов из `iitolstykh/LLMTrace_classification` (test, метка `ai`;
  генераторы: gpt-3.5/4o, GigaChat, YandexGPT и др.), 400–2500 символов.
- **Корпус**: 800 human-текстов LLMTrace → 12 616 предложений (`research/data/corpus.txt`).
- **Метрика перплексии** (этап 1): 3-граммная WittenBell LM на human-корпусе; цель — **повысить** ppl.
- **Детектор** (этап 2): `toiletsandpaper/russian-ai-text-detector-bert` (ONNX int8, MIT,
  локально, без ключей). Базовая линия: ИИ-тексты — средний скор 0.967, 29/30 определены как ИИ
  (ai_028 — короткий ложный пропуск); human-тексты — средний 0.112 (`detector_baseline.csv`).
- Все тексты, метрики и логи: `research/results/` (summary.csv, matrix.md, detector_scores.csv,
  humanized/<config>/<id>.txt, logs/ — на диске, logs не в git).

**Ранжирование по детектору (Δonnx вниз = хорошо)**:
1. **Омоглифы (`--mode 4`), n=1 — 29/30 снято с детекции, средний скор 0.967 → 0.036**;
   текст визуально не меняется (a↔а, o↔о, p↔р, B↔В…), при этом ppl растёт (+794) —
   обе метрики сходятся в правильную сторону. n=2 — 11/30, n=3 — 7/30.
2. ngram, n=1, порог 0.15 — 4/30 снято, средний −0.15 (41% замен, читаемость заметно страдает);
3. ngram, n=1, порог 0.25 / 0.2 — по 1/30, −0.04 / −0.03;
4. pmi, n=1, порог 0.25 — −0.019, без flip;
5. lesk и все sklearn-модели — эффект ≈ 0;
6. синонимы при t=0.1 (98% замен) — 22–24/30 снято, но текст нечитаем («Талонная прибыльность…
   какую-либо вкладчик добывает от купюр»); непригодно.

## Этап 2: sklearn-модели (nb, logreg, svm, rf, gbm, lsa)

Обучены на парах (контекст, слово) → «подходит»: 30k позиций корпуса, позитивы — настоящие
слова, негативы — случайные (`research/train_all.py`, артефакты в `models/`).
Результат: ни по ppl (−3…+6), ни по детектору (≈0) не отличаются от lesk нулевого эффекта;
частотность/разреженные BoW-признаки на 12k предложений не дают контекстной дискриминации.
LSA чуть разреженнее в выборе кандидатов, но тоже без эффекта на детектор.

## Ключевые выводы

1. **Омоглифы (`--mode 4`) — единственный эффективный инструмент**: 29/30 ИИ-текстов снято
   с детекции при n=1, текст визуально не отличим, перплексия растёт (+794). Детектор
   toiletsandpaper не нормализует смешанные алфавиты. Рекомендуемая конфигурация:
   `--mode 4 --n 1` (или `--n 2` для щадящего режима — 11/30).
2. **Синонимические режимы (1–3) против детектора слабы**: 13–18% замен дают ≈0; 41%
   (ngram t0.15) дают 4 flip; 98% (t0.1) дают 23 flip ценой полного разрушения текста.
3. **Метрики частично расходятся**: lesk поднимает ppl (+24) но не двигает детектор; ngram —
   обратное. Только омоглифы двигают обе метрики в целевую сторону.
4. **Режим выбора (1/2/3) — слабый рычаг**: почти всегда проходит один кандидат либо
   равновероятны (tie); режимы дают почти идентичные результаты.
5. **Качество синонимов**: склонение/согласование работает; словарь шумный («сие», «прайс»),
   при плотности >25% читаемость деградирует. Омоглифы читаемость не меняют (визуально).
6. **Удалённый бесплатный API**: Sapling — без русского; GPTZero — требует ключ (401,
   бесплатная регистрация); полноценная замена — локальный детектор toiletsandpaper
   (бесплатно, без ключей, интегрирован в `research/detectors.py`).
7. PCFG (Stanford Parser) признан непригодным: нет готовой русской грамматики.
   Эмбеддинги (w2v/fasttext) не внедрялись: веса 200 МБ–4 ГБ при сомнительной пользе
   по итогам этапа 2; при желании — легковесный navec (~60 МБ) вместо gensim.

## Как воспроизвести

```bash
python research/data_prep.py        # тексты + корпус (datasets-server, ~5 МБ)
python research/train_all.py        # артефакты моделей в models/
python research/evaluate.py --models lesk,ngram,pmi --ns 1,2,3 --thresholds 0.25,0.5
python research/detector_check.py   # onnx-оценка всех сохранённых вариантов
```
